# vizir 信息图目录

仓库里已经有**两套论点不同的图**。不要合并，也不要在本目录再画一张分层架构信息图。

本目录只收现行长图 `vizir-explainer/`。旧架构图住在上一级 `docs/`，本波原样保留、不重画。本目录没有第三张图。

## 分工

| 图 | 路径 | 论点 | 本波 |
| --- | --- | --- | --- |
| 旧架构图 | `docs/architecture-infographic.*`（tex / png / svg / pdf） | 可视化编译器架构：从语义 YAML 到矢量输出的确定性编译管线。VizIR 不是一个渲染器，而是一组分层 IR：每一层拥有明确的职责边界，下层只消费上层的规范化契约，绝不反向推断语义。 | 旧图。保留。不重画、不编译、不改样式。 |
| 现行长图 | `docs/infographics/vizir-explainer/` | vizir 把可视化文档当编译器问责对象——每个 Scene2D 节点携带完整责任链可被 explain 质询，每次后端编译都逐节点做 capability 谈判（不支持即稳定诊断码 fail-loud，绝不静默消失），每条 ScenePatch 局部补丁都受 revision 校验并与全量重算语义等价。 | 现行交付。证据冻结。页面零代码坐标。细节以该目录 `README.md` / `contract.md` 为准。 |

两套图回答的问题不同，合成一张会同时丢掉两边的论点：

- 旧架构图回答：分层 IR 各层职责边界怎么画。
- 现行长图回答：节点责任链怎样被质询，能力谈判失败为何必须响、局部补丁与全量重算如何等价。

## 先看哪一张

先看 `vizir-explainer/`。它是现行交付：节点责任链怎样被质询，能力谈判失败为何必须响、局部补丁与全量重算如何等价，数字来自冻结证据，页面本身不带代码坐标。入口是该目录的 `index.html`；重建链见该目录 `README.md`，声明锚点见 `VERIFICATION.md`。

只有需要静态架构总览（分层 IR 编译管线总览）且能接受代码标识符上台时，才打开旧图。旧图把标识符画上台、或与现行论点不一致，都不是开工重画的许可；要修，另开任务，且须先从 `architecture-infographic.tex` 复现已提交产物再改同一份源。

`docs/architecture.html` 是同主题的交互概览页，不是本目录的第三张信息图；本波不改。
